# Laya: проверка применимости (spike, 2026-11-14)

**Вывод: Laya хуже пайплайна на обоих жёстких разбиениях, уверенность при выборе из 11+ вариантов не калибрована, инъекция меняет её ответ в 36% строк. Заменять наш классификатор нельзя; допустимо только как второе мнение (флаг на ручную проверку, ничего не переписывает).**

## Установка
- `python -m venv` + `pip install laya` (Windows, Python 3.13): 184 с, без ошибок. laya 0.4.31, torch 2.15.0+cpu, transformers 5.23.0.
- venv 857 МБ; при первом запуске с HF скачивается 2,26 ГБ (english + multilingual), ~75 с.
- GPU не используется (CPU-torch из PyPI). Латентность CPU: 237–247 мс/строка батчем 16, 474 мс по одной.
- Лицензия: Apache 2.0.

## Постановка
State = masked description + GL номер/название + quantity + unit. Вопрос `choice` по ef_id: ef_id, встречавшиеся с этим GL в train-фолде, плюс совместимые по единице activity-факторы; для невиданного GL — все совместимые activity-факторы, все SP_* и EXCLUDE. Фолды как в eval_hard (group_folds, K=5, seed 42).

Библиотека сама предупреждает: для choice с 11+ вариантами уверенность считать некалиброванной. Порог с точностью ≥0,97 есть только на разбиении по шаблону (p ≥ 0,9995: 0,979 при покрытии 34%, где пайплайн и так прав в 522 из 533). На разбиении по GL такого порога нет (p ≥ 0,9995 → 0,94). При p ≥ 0,9995 на GL-разбиении Laya исправляет 38 из 282 ошибок пайплайна и ломает 9 верных; на шаблонном исправляет 11, ломает 9.

## Инъекции
50 строк с инструкцией в сыром описании: ответ изменился в 18/50 (15 — на EXCLUDE). Вход Laya — только текст после `strip_injection`.

## Рекомендуемый гейт
1. В расчёт не встраивать: ef_id и tCO2e считает только пайплайн.
2. Опционально флаг `laya_disagree` (p ≥ 0,9995 и другой ef_id) → ручная проверка, без перезаписи. Вход только после `strip_injection`.
3. Перепроверять порог после CUDA-torch и при каждом обновлении laya.
